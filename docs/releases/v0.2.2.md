# MikuBox v0.2.2

修复连接后清理后台可能伴随网络卡顿的问题，并完善 VPN 恢复与停止行为。

- 分两步启动 VPN：先初始化配置、供应器、DNS 和路由，再建立并交接 Android TUN。慢速供应器下载期间不接管设备流量，取消或失败会释放核心和监听端口。
- Android 12 及以上跟随系统选择的最佳物理网络；旧版本回退选择排除 VPN，不再依赖网络枚举顺序。底层网络未改变时不重复重设，避免 Wi-Fi 被错误换成蜂窝网络。
- 配置过的 VPN 优先使用 `systemExempted` 前台服务类型；系统不允许时回退到 `specialUse`。明确声明任务划掉不停止服务、支持始终开启 VPN。
- 所有主动断开入口先取消恢复意图；启动中取消、重复启动和迟到的恢复事件不会重新连上。启动准备有超时保护，恢复连续失败会退避，三次失败后暂停，手动连接可重试。
- VPN 设置区分系统电池优化、始终开启 VPN 与厂商后台权限。为 OnePlus / OPPO / realme 提供对应说明和应用设置入口。

## OnePlus / ColorOS

在 MikuBox 的 VPN 设置中申请忽略电池优化，并进入应用设置允许后台运行；如系统提供自启动或关联启动选项，也需允许。希望系统主动维护连接时，可在系统 VPN 设置中打开“始终开启 VPN”。这些开关互不替代。

Android 强行停止及部分厂商清理策略可以终止 VPN，应用无法保证进程永不被杀。此次本地设备覆盖为 Android 16 arm64 模拟器，未连接 OnePlus 12 / ColorOS 16 真机；厂商清理行为仍需真机验证。

平台依据：[VPN 生命周期与始终开启](https://developer.android.com/develop/connectivity/vpn)、[前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)、[用户停止前台服务](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping)。

## 验证

- 57 项 JVM 回归通过，Go bridge 全部测试通过；Lint 为 0 错误、256 警告；arm64-v8a、armeabi-v7a、x86_64 调试 APK 构建通过。
- Android 16 arm64：MIXED / gVisor 两种栈均通过独立 UID 的 4 KiB、64 KiB、384 KiB 双向完整性检查；指定代理的 384 KiB 请求通过受限代理服务验证，无法直连绕过。
- 阻塞供应器下载时没有 VPN 接管，独立应用仍能联网；放行后 VPN 保持 Wi-Fi；启动中取消与主动停止不会被迟到恢复事件重新拉起；停止后 TUN、TCP / UDP 10808 端口释放。
- 系统服务记录显示 `systemExempted`（`0x400`）。Home 后普通 `am kill` 与最近任务划掉均保留连接和真实转发；`kill -9` 模拟意外死亡后观察到新进程约 32 秒恢复，独立 UID 的直连和代理完整性检查再次通过。恢复时间受系统调度影响，不作为保证。

复现设备用例：先运行 `python3 tools/runtime-network-fixture.py`，在隔离模拟器安装调试 APK 和测试 APK、授予 VPN 使用权限，再运行 `am instrument -w -e lifecycle true com.mikubox.mihomo.test/com.mikubox.mihomo.RuntimeSmokeInstrumentation`。普通网络用例将参数改为 `-e stack MIXED` 或 `-e stack GVISOR`。用例会创建、选择测试配置，应在专用测试数据上执行。
