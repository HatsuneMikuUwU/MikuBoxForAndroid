# MikuBox v0.2.3

修复连接恢复期间的流量空转，以及 gVisor 停止后空闲 TUN 仍继续接管流量的问题。本版包含未发布的 v0.2.2 草稿中的生命周期改进。

## 连接与停止

- 修复 sing-tun v0.4.21 过滤层丢失 gVisor 解除绑定信号的问题。停止时会唤醒并等待读取线程退出，再释放 TUN；不再依赖下一次网络流量唤醒残留读取器。
- 先准备配置、供应器、DNS 和路由，再建立 Android TUN。供应器下载较慢时不提前接管设备网络；准备过程有超时和取消处理。
- Android 12 及以上跟随系统选择的最佳物理网络，旧版本回退选择排除 VPN。底层网络和 DNS 不变时不重复重设，避免误切到蜂窝网络。
- 主动断开先取消恢复意图；重复启动、启动中取消和迟到的恢复事件不会重新连上。恢复连续失败会退避，三次失败后暂停，手动连接可以重试。

## 后台运行

- 配置过的 VPN 优先使用 `systemExempted` 前台服务类型，系统不允许时回退到 `specialUse`；声明任务划掉不停止服务、支持始终开启 VPN。
- VPN 设置区分 Android 电池优化豁免、始终开启 VPN 与厂商后台权限，并提供 OnePlus / OPPO / realme 说明和应用设置入口。

OnePlus / ColorOS 用户可在 MikuBox 的 VPN 设置中申请忽略电池优化，在系统应用设置允许后台运行；如系统提供自启动或关联启动选项，也需允许。希望系统主动维护连接时，可在系统 VPN 设置中打开“始终开启 VPN”。这些开关互不替代。

Android 强行停止及部分厂商清理策略可以终止 VPN，应用无法保证进程永不被杀。当前设备验证环境为 Android 16 arm64 模拟器，未连接 OnePlus 12 / ColorOS 16 真机；厂商一键清理行为仍需真机验证。系统撤销或重建 VPN 时已有连接也可能中断。

平台依据：[VPN 生命周期与始终开启](https://developer.android.com/develop/connectivity/vpn)、[前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)、[用户停止前台服务](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping)。

## 回归验证

新增 gVisor 解除绑定回归，未经修补的 sing-tun 会失败。Go 模块缓存保持不变，生成的依赖副本由测试和所有 ABI 构建共同使用，防止测试代码与 APK 中的核心不一致。

运行 `./gradlew :app:testDebugUnitTest :app:testMihomoBridge :app:lintDebug` 检查 Kotlin、原生补丁和静态检查。原生测试应使用此 Gradle 入口，以加载发布构建使用的依赖补丁。

设备回归使用专用测试数据：运行 `python3 tools/runtime-network-fixture.py`，安装调试 APK 和测试 APK并授予 VPN 权限后，运行 `am instrument -w -e lifecycle true com.mikubox.mihomo.test/com.mikubox.mihomo.RuntimeSmokeInstrumentation`。网络完整性用例将参数改为 `-e stack MIXED` 或 `-e stack GVISOR`。用例会创建和选择测试配置。

## 签名产物验收（2026-09-28，Android 16 arm64 模拟器）

签名 v0.2.3（versionCode 203；arm64-v8a 已实际下载校验，SHA-256 与 GitHub 元数据一致，签名证书与 v0.2.0/v0.2.1 相同，内含 native revision 2026-09-28.2）通过以下检查：

- 从签名 v0.2.2 覆盖升级后，应用 UID、选中配置和全部配置保持不变。
- 空闲停止：GVISOR 三次分别在 2.234 / 0.262 / 0.963 秒内 TUN 消失，MIXED 三次 0.104 / 0.112 / 1.060 秒；每次停止后 Android 侧 TCP 与 UDP 的 10808 端口都能重新绑定。
- 独立 UID 的真实转发：直连 4 KiB / 64 KiB / 384 KiB，以及必须经代理的严格端点 384 KiB（绕过代理会被端点拒绝），GVISOR 与 MIXED 两栈都通过；两栈停止后直连仍通过。
- 实际从最近任务划掉：任务从最近任务列表消失，服务、TUN 与转发保持。
- 前台服务类型为 `0x00000400`（systemExempted）。
- 主动停止后 75 秒内没有重新连接，TUN 与端口保持释放，VPN 通知已移除。
- `kill -9` 后共 10 轮恢复：每轮在新进程上重新验证转发通过。恢复多由守护告警触发（30 秒周期加启动时间，约 42–52 秒），个别轮次在告警即将触发时被杀，7.8 秒完成恢复。
- 20 秒慢供应器：准备期间不建立 TUN，独立 UID 仍可正常上网，供应器完成后 TUN 才建立。
- 物理网络 Wi-Fi → 蜂窝 → Wi-Fi：底层网络与转发都跟随切换。

已知限制：未连接 OnePlus 12 / ColorOS 16 真机，厂商清理、自启动与关联启动行为仍需真机验证。本次验收开始前的会话曾在宿主严重卡顿（窗口管理器锁等待 5.320 秒、多处约 4 秒消息延迟）时观察到恢复后一次 64 KiB 直连超时；本轮在健康环境与人为加负载（宿主 1 分钟负载达 30、客体内 10 个 CPU 占用进程）下共 33 次探测、10 轮 `kill -9` 恢复均未复现，也未能定位应用侧机制，未据此修改代码。

## 走查环境准备（包名与同名旧包）

本仓库构建出的应用包名是 `com.mikubox.mihomo`（`app/build.gradle.kts` 的 `applicationId`）。历史源码曾以 `top.uwu.mikubox` 为包名，走查用的测试模拟器上可能残留 2026-09-20 安装的旧 UwU-1.0.0 产物；另外仓库外交接单记录过同设备另装有 SagerNet 系应用 `uwu.mb4a`，其显示名同样叫 MikuBox 并注册了 `clash://` 深链。三个同名条目会让 `clash://` 的"打开方式"弹窗出现多个 MikuBox，干扰深链与授权走查。

走查前先列出并清理同名旧包（所有文档与命令一律使用 `com.mikubox.mihomo`）：

```bash
adb shell pm list packages | grep -iE "uwu|mb4a"
adb uninstall top.uwu.mikubox   # 旧 UwU-1.0.0 产物（历史包名，仅存在于旧安装）
adb uninstall uwu.mb4a          # 包名出处仅见仓库外交接单；pm list 未列出则无需处理
```

清理后可复核深链处理器只剩被测应用一个：

```bash
adb shell cmd package query-activities -a android.intent.action.VIEW -d "clash://test"
```

被测应用自身处理 `clash://` 的组件只有 `com.mikubox.mihomo.service.MikuImportActivity`。
