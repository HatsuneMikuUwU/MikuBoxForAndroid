# 主页模式切换（2026-09-20）

连接气泡上方新增“规则 / 全局 / 直连”三段滑块，颜色跟随 Material 主题，位置跟随底部安全区域及快捷操作栏。列表底部留白也跟随控件高度，避免展开后挡住最后一项。

交互顺序：

- 规则与直连互切：指示滑块横移 230ms，保持收起。
- 规则/直连进入全局：先横移 230ms，再用 200ms 展开全局出口行。
- 全局离开：先横移到新模式，再用 200ms 收起出口行。
- 连续点击取消旧动画，从当前画面继续；系统关闭动画时立即到达终态。
- 进入全局不弹窗。仅主动点击居中的出口名称或再次点击已选中的“全局”才打开单选列表，显示代理组和代理节点。

模式直接调用 mihomo setMode，同时保存供下次启动使用。出口选择按配置 ID 保存；未连接时读取该配置的 YAML/JSON 节点和组，已读取过的 GLOBAL 成员也缓存供离线选择。连接启动后应用保存的出口；节点已被删除或 provider 内容变化导致核心拒绝时，清除失效选择并显示核心实际出口，不伪装已生效。

离线时无法凭空列出从未下载/读取过的远程 provider 节点；可以先选择配置中声明的代理组。这里选择的是 GLOBAL 的出口，可以是一个组或一个节点，不会更改该组内部的自动选择策略。

验证结果：

- JDK 21 下 `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 成功；30 项测试全部通过，Lint 0 错误、225 个警告（含 4 项新增的 KTX/文本拼接风格建议）；三架构 Debug APK 签名验证通过。
- Android 16/API 36 arm64 模拟器确认：规则/直连互切、全局展开和收起、不自动弹窗；录屏抽帧验证先横移再改变高度。面板高度为 60dp/100dp。
- 未连接时分别选择 PROXY 组和 AuditSOCKS 节点；应用强制停止后重新启动，仍显示选择的节点。
- 启动连接后，受控 HTTP 请求返回 `mode-switch-ok`；日志同时出现测试 SOCKS 服务 `proxying 10.0.2.2:18889` 和 mihomo `using GLOBAL`，证明保存的出口实际参与转发。
- 保持同一 VPN 连接切到直连，新请求日志为 `using DIRECT`；切回规则，新请求为 `match GeoIP(lan) using DIRECT`。三次 HTTP 请求均成功。
- 设备测试顺带发现普通 URI 可能被 Android 宽松 Base64 解码误吞，已让明文 URI 跳过 Base64 解码，并增加不同名称长度的回归。自定义 GLOBAL 也只提供其声明的成员。
