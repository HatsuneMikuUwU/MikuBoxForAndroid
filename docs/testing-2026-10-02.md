### 构建修复（1 条）

**N25（low，build）WSL→Windows gradlew 桥接以 $* 拼参数，含空格/元字符的参数碎裂**
位置：`gradlew:108`（exec "$__cmdexe" /c "set JAVA_HOME=$JAVA_HOME&& ${__pathset}gradlew.bat $*"）。
复核：构建/测试命令退出码即证据。$* 先被 POSIX sh 按空白拆词、再被 cmd 二次解析，含空格或 cmd 元字符（&、^、%、"）的参数会碎裂或改变语义（如 `-PappVersionName="0.2.3 beta"`、--tests 带空格的过滤串）；原注释只论证了 JAVA_HOME/PATH 值本身不含 % 和 &&，未覆盖任意构建参数。
处置与实施：逐参数白名单（字母数字 + gradle 实际携带标点 `- + . / : = _ @ * ?` 与 Windows 路径反斜杠），命中即拒绝并报错 exit 2，守卫条件（case+cmd.exe 探测+/proc/version）不动。撰写初稿时工作树抽查证实 `gradlew:106-124` 已含该白名单与 exit 2。
验证口径（修订时更正并补实测）：复验记录原称"行为级验证因 WSL 侧无 Linux JDK 不可达（仅代码级）"——该说法范围夸大。按实现分层：白名单拒绝在 sh 层 exit 2，发生在调用 Windows gradlew.bat 与任何 Java 之前，**验证拒绝路径不需要 JDK**；需要 Linux JDK 的只是"合法参数经桥接正向跑通构建"这一条路径。修订时实测（修订时执行）：在 WSL 侧以驱动器号 JAVA_HOME（`JAVA_HOME="D:\Program Files\Java\JAVA21"`，命中 gradlew:74-76 的桥接守卫）执行 `./gradlew "-Pbad arg" --version`，输出来自 `gradlew:115-121` 的白名单拒绝文案（"refusing to pass this argument through the WSL cmd.exe bridge: -Pbad arg …"），其后无任何 Gradle/JVM 输出——拒绝路径被行为级触发成立；对照试探（未设驱动器号 JAVA_HOME）走 UNIX 分支死于 Java 缺失检查，证明该环境无可用 Linux JDK（与材料记录一致）。退出码读数经 wsl/bash/cmd 多层引号转写不可靠（实测回显 rc=0 与 exit 2 预期不符，归因于引号层级），不作为证据引用。结论：拒绝路径已验证；正向路径（合法参数跑通构建）仍因 WSL 无 Linux JDK 未验证，如需验证应改在 cmd.exe/PowerShell 直接调用 gradlew.bat。
